# 에이전트 네이티브 도구

에이전트가 단순한 보조 기능이 아니라 **분석·편집·제작·렌더링 작업의 직접 실행자**가 되도록 설계된 소프트웨어와 인터페이스를 정리한다.

## 다루는 범위

- 에이전트가 CLI, MCP, API, 프로젝트 파일 또는 구조화된 작업 단위를 통해 직접 조작하는 도구
- 이미지·음성·영상·개발 환경 등에서 사람이 수정 가능한 중간 산출물을 남기는 워크플로
- 권한, 동의, 검수, 되돌리기, 감사 가능성을 포함한 안전한 에이전트 실행 설계

## 검토 관점

1. **작업 인터페이스**: 에이전트가 호출할 수 있는 기능·입력·결과 형식이 명확한가?
2. **편집 연속성**: 결과가 레이어, 프로젝트 파일, HTML 등 사람이 이어서 수정할 수 있는 형태로 남는가?
3. **권한과 안전성**: 분석 대상 소유권, 음성·개인 데이터 동의, 외부 실행 권한을 어떻게 통제하는가?
4. **검수와 복구**: 사람이 결과를 검토하고 수정·취소·재현할 수 있는가?
5. **도입 판단**: 데모의 가능성과 실무의 안정성·성능·라이선스·유지보수 비용을 구분했는가?

## 다른 주제와의 연결

- `02-에이전트-친화적-웹`: 웹 기능을 에이전트가 사용할 인터페이스로 설계하는 관점과 연결된다. 다만 이 주제는 웹에 한정하지 않는다.
- `03-에이전트-설정`: 도구 연결·스킬 설치·실행 권한 설정을 다루되, 제품별 설정 자체는 해당 주제에 둔다.
- `01-AI-네이티브-SDLC`: 에이전트가 개발·제작 워크플로에 참여할 때 검증·승인·가드레일을 적용하는 관점과 연결된다.

## 자료 추가 기준

- 사례 파일명은 루트 [AGENTS.md](../AGENTS.md)의 명명 규칙을 사용한다.
- 영상·홍보 자료의 기능 주장과 공식 문서·저장소에서 확인한 사실을 구분한다.
- 도구의 라이선스, 실행 위치(로컬·클라우드), 권한 범위, 중간 산출물, 검수·복구 방법을 기록한다.
- 외부 도구의 소스 코드나 설치 파일은 이 주제에 복사하지 않는다. 재사용할 도구를 보관할 필요가 있고 라이선스가 확인된 경우에만 `99-도구/`에 별도로 둔다.
