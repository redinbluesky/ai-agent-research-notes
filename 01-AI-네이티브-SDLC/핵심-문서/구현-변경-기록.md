# 구현-변경-기록.md

## 목적

`구현-변경-기록.md`는 승인된 `plan.md`에 따라 실제로 변경한 코드·설정·테스트와 계획에서 달라진 판단을 기록한다. 코드 diff와 테스트가 구현의 1차 산출물이지만, 변경 이유와 검증 근거를 짧게 연결해 리뷰와 운영 인수인계를 돕는다.

## 출처에서 확인한 내용

- 에이전트가 작업하는 저장소에는 빌드·테스트·린트 명령, 주요 규칙, 아키텍처 문맥을 버전 관리된 규칙 파일로 제공할 수 있다.[9]
- 작업 완료 전 에이전트가 테스트·빌드·스크린샷 비교 같은 도구 기반 검증을 수행하도록 하는 피드백 루프가 권장된다.[1]

## 실무 가이드

- 관련 `intent.md`, `spec.md`, `plan.md`, PR을 링크한다.
- 변경 파일과 각각의 변경 이유를 요약한다.
- 계획과 실제 구현이 달라졌다면 이유·영향·승인 여부를 남긴다.
- 생성된 코드·의존성·설정·마이그레이션 변경을 구분한다.
- 비밀값, 사용자 데이터, 운영 자격 증명은 기록하지 않는다.

## 권장 템플릿

```md
# 구현 변경 기록: [기능 이름]

Related intent: [경로]
Related spec: [경로]
Related plan: [경로]
Related PR: [URL]

## 변경 요약

## 변경 파일과 이유
- `[경로]`:

## 계획과 달라진 점
- 없음 / 변경 내용과 이유:

## 구현 시 확인한 위험

## 검증 근거
- [ ] build
- [ ] test
- [ ] lint
```

## 점검 목록

- [ ] 변경이 승인된 계획과 연결되는가?
- [ ] 변경 파일과 이유가 명시됐는가?
- [ ] 계획과 달라진 점을 기록했는가?
- [ ] 검증 결과가 PR과 연결되는가?
- [ ] 비밀값이나 민감정보가 없는가?
