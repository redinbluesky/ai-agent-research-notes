# 구현과 에이전트 가드레일

## 목적

AI 에이전트가 코드와 테스트를 빠르게 작성하더라도, 팀의 아키텍처·보안·변경 범위 규칙 안에서 작업하게 만드는 방법을 정리한다.

## 출처에서 확인한 내용

- 에이전트가 작업을 시작할 때 필요한 빌드·테스트·린트 명령, 저장소 규칙, 자주 발생하는 실수는 버전 관리되는 규칙 파일에 제공할 수 있다.[1]
- 테스트·빌드 같은 무거운 검증은 커밋 또는 PR 단계에 두고, 편집 단계의 훅은 빠르고 변경 범위에 맞게 유지하는 것이 권장된다.[1]
- 반드시 지켜야 하는 정책은 안내성 지침만으로 충분하지 않을 수 있으므로, 훅이나 결정론적 검사로 강제할 수 있다.[1]

## 실무 가이드

### 1. 규칙 파일에 최소 문맥을 기록한다

`AGENTS.md` 또는 도구별 규칙 파일에는 다음을 짧고 검증 가능하게 둔다.

- 빌드·테스트·린트 명령과 정상 종료 기준
- 주요 디렉터리와 아키텍처 경계
- 금지하거나 승인 전용으로 둘 변경: 인증, 결제, 개인정보, 인프라, DB 마이그레이션
- 기능 작업 시 `intent.md`, `spec.md`, `plan.md`을 읽고 갱신하는 기준

### 2. 가드레일의 강도를 나눈다

| 수준 | 수단 | 예시 |
|---|---|---|
| 안내 | 규칙 파일, skill, 템플릿 | API 오류 형식, 코드 스타일 |
| 자동 확인 | formatter, lint, 정적 분석 | 포맷·타입·취약점 검사 |
| 강제 차단 | hook, CI 정책, 권한 제어 | 비밀값 커밋, 보호 경로 편집, 승인 없는 운영 배포 |

규칙 파일은 에이전트가 올바르게 행동할 가능성을 높이는 도구이고, 훅과 CI는 위반 자체를 차단하는 도구로 구분한다.

### 3. 계획과 구현의 차이를 기록한다

구현 중 변경 범위·위험·검증 방법이 `plan.md`와 달라지면, 코드 변경과 같은 PR에서 계획도 갱신한다. 리뷰에서는 코드뿐 아니라 계획 대비 차이를 함께 확인한다.

### 4. 권한은 최소화한다

에이전트에는 작업에 필요한 읽기·쓰기 범위만 제공한다. 특히 운영 환경 자격 증명, 비밀값, 보호 브랜치 직접 반영 권한은 기본 권한에 포함하지 않는다.

## 점검 목록

- [ ] 에이전트가 실행할 build/test/lint 명령이 한 곳에 정의되어 있는가?
- [ ] 보호 경로와 사람 승인 대상이 명시되어 있는가?
- [ ] 비밀값 검사와 보호 경로 차단이 자동화되어 있는가?
- [ ] 계획에서 벗어난 구현이 PR에서 설명되는가?
- [ ] 구현 에이전트와 최종 승인자의 역할이 분리되어 있는가?
