# 운영-인시던트-기록.md

## 목적

`운영-인시던트-기록.md`는 운영 지표의 이상, 인시던트, 대응·복구·재발 방지 결정을 기록하고, 결과를 다음 intent와 eval로 연결한다.

## 출처에서 확인한 내용

- CI 테스트 실패율, 배포 뒤 오류율, PR 리드타임 등 기준선이 있는 지표를 감지 대상으로 삼고, 감지는 결정론적 규칙으로 유지하는 방식을 제시한다.[5]
- 이상 수준에 따라 기록, 읽기 전용 진단, PR 또는 사전 승인된 runbook 실행을 나눌 수 있다.[5]
- 인시던트 수정이 배포되면 해당 사례를 regression eval로 추가하고, 더 큰 개선은 새로운 `intent.md`로 시작할 수 있다.[5]

## 실무 가이드

- 감지 시각, 지표, 기준선, 영향 범위와 증거를 기록한다.
- AI의 진단 가설과 사람이 확인한 원인을 구분한다.
- 대응 수준, 승인자, 실행한 runbook, 복구 상태를 적는다.
- 고객·데이터·보안 영향과 외부 공지 필요성을 별도 판단한다.
- 재발 방지 조치를 test·eval·가드레일·새 intent 중 어디에 반영할지 결정한다.

```md
- 사람 확인:

```
