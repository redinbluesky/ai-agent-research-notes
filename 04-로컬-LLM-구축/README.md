# 로컬 LLM 구축

AI 에이전트를 구동할 **로컬·온디바이스 LLM의 선정·설치·서빙·성능 검증 방법**을 정리한다. GPU VRAM이 아닌 DRAM 중심 구축, 서빙 엔진, 양자화 등급 선택처럼 에이전트 실행 환경과 직결되는 주제를 다룬다.

## 핵심 원칙 (Strata 사례 기준)

아래 원칙은 Strata 서빙 엔진과 Qwen 3.8 Flash Next 사례에서 확인된 내용으로, Strata가 지원하는 MoE + N-gram 임베딩 계열 구축에 한정된다. 다른 서빙 엔진·모델로 일반화하지 않는다.

1. 모델 적합성은 VRAM 용량이 아니라 **DRAM 용량으로 결정**한다. (예: 32GB→Coder, 48GB→IQ2_XS, 64GB→IQ3_XXS, 96GB+→IQ3_S/4비트)
2. DRAM 중심 서빙은 MoE + N-gram 임베딩 계열 아키텍처에 특화되어 있으며, dense 모델에는 적용할 수 없다.
3. 커뮤니티 양자화 모델은 순정과 지능 차이가 있으므로 속도 수치와 지능 평가를 분리해 본다.
4. 고밀도(4비트 이상) 모델이 DRAM을 초과하면 SSD 스트리밍으로 급락하므로 NVMe SSD와 메모리 여유(OS 점유분)를 고려한다.
5. 에이전트에게 설치·측정을 위임하는 실무는 흔하나, 실행 권한 부여는 가드레일 관점에서 검토가 필요하다.
