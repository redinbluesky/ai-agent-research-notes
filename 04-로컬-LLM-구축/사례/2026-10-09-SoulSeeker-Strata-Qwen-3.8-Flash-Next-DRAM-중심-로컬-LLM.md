## 한 문장 결론

Strata 서빙 엔진은 Qwen 3.8 Flash Next(약 125B + N-gram 임베딩 51B)를 VRAM이 아니라 **DRAM(시스템 메모리)에 압축 적재하고 필요한 전문가(MoE) 레이어만 VRAM으로 가져와** 연산함으로써, RTX 3060 12GB 같은 저용량 GPU에서도 실사용 가능한 토큰 속도를 냈고, 이는 "VRAM 중심"이던 로컬 LLM 구축 기준을 "DRAM 중심"으로 옮기는 변화로 해석된다.[1]

## 문제와 제안된 메커니즘

- 문제: Qwen 3.8 Flash Next는 MoE 기반 초대형 모델로, 기존 방식(VRAM 적재 또는 단순 CPU 오프로딩)으로는 고가 GPU(5090×2 등)가 필요했고, 저용량 VRAM에서는 한 자리 수 토큰 속도밖에 나오지 않았다.[1]
- 제안: Strata는 2~3비트 수준으로 압축(양자화)한 가중치를 DRAM에 두고, 24,576개 전문가 중 실제로 필요한 레이어만 GPU로 가져와 압축을 풀며 연산한다. MTP(다중 토큰 예측/추측 디코딩)로 다음 토큰을 예측해 가져올 전문가 그룹을 미리 특정하는 구조다.[1]
- 전제 조건: MoE 아키텍처 + N-gram 임베딩 사용 모델에 특화되어 있으며, 현재 공식적으로 Qwen 3.8 Flash Next 계열만 지원한다. dense 모델(예: Qwen 3.8 27B)은 이 구조에 들어올 수 없다.[1]
- 주의점: 순정 모델이 아니라 개발자·커뮤니티가 자체 양자화한 모델을 사용하므로 순정과의 지능 차이가 있다.[1]

## 영상이 제시한 실증

테스트 환경: Core Ultra 7 270K Plus, Z890(PCIe 5.0), Windows 11, 메모리 64GB → 192GB(Bywin DDR5-6000 CL26 48GB×4)로 증설, GPU 9종 전수 테스트(5090×2, 5090, 5080, 5070 Ti, 5070, 5060 Ti 16GB, 3090, 3080 Ti, 3060 12GB). 설치·성능 측정은 OpenCode Desktop + Muse Spark 1.3 Free 에이전트에게 맡겼다.[1]

설치 과정 요약: GitHub 릴리즈(CUDA 12) 다운로드 → AI에게 `AI_SETUP.md` 기반 설치·세팅 위임 → 첫 구동에서 IQ3_S가 메모리 부족으로 실패, Coder 모델은 성공 → IQ2_XS·IQ3_XXS 추가 다운로드 → IQ3_XXS 구동 성공. 저자는 "VRAM이 아니라 메모리 기준으로 모델을 픽하는 것이 중요하다"고 결론짓는다.[1]

### 디코딩 토큰/초 (MTP 켜짐 기준, 영상 그래프 낭독값)

| GPU | IQ2_XS | IQ3_XXS | IQ3_S | Coder |
|---|---|---|---|---|
| RTX 3060 12GB | 48 | 43 | 36 | 42 |
| RTX 3080 Ti 12GB | 72 | — | 50+ | 60+ |
| RTX 5060 Ti 16GB | 78 | — | 50+ | 62 |
| RTX 5070 12GB | 86 | — | 60+ | 72 |
| RTX 3090 24GB | 115 | 100 | 93 | 100+ |
| RTX 5070 Ti / 5080 16GB | 120+ (두 카드 성능 차이 없음) | 3090 대비 87~95% | 버팀 | 94~101 |
| RTX 5090 32GB | 196 (MTP off 130, +47%) | 182 | 172 | 196 |
| RTX 5090×2 (레이어 24+24 분할 + 파이프라이닝) | 273 (+39%) | 291 (+42%) | 235 (+37%) | 277 (+55%) |

- 프리필: 3060에서도 900대, 3080 Ti 2,000~2,500, 5070 Ti/5080 2,900~3,400, 5090 5,000~6,000+, 5090×2(분할) 6,839. 프리필은 모델 양자화 수준 차이가 크지 않게 나타남.[1]
- 5090×2는 디코딩에서는 이점이 크지만 프리필에서는 13% 수준 개선에 그침. 저자는 "5090 한 장이 가성비"라고 평가.[1]
- MTP는 대체로 40% 안팎의 성능 향상(채택률 85~100%)을 주며 켜두는 것이 유리하다고 권고. 단 5090×2 IQ3_XXS 프리필처럼 MTP가 오히려 성능을 떨어뜨리는 조합도 관측.[1]

### 메모리 요구량 (VRAM이 아니라 DRAM이 병목)

| 모델 | DRAM 사용량(관측) | 저자 권고 |
|---|---|---|
| Coder(IQ1급) | 약 26~34GB | 32GB에서 시도 가능 |
| IQ2_XS | 약 40~48GB | 최소 48GB |
| IQ3_XXS | 약 46~52GB | 최소 48GB, 권장 64GB |
| IQ3_S | 약 53GB+ | 최소 64GB, 권장 96~128GB |

- 같은 모델은 GPU가 무엇이든 DRAM 사용량이 거의 일정했고, VRAM 12GB(3060)에서도 모든 모델이 구동됐다. 64GB 환경에서 IQ3_S가 Out-of-Memory로 실패한 사례를 들어, 윈도우가 최대 10GB 안팎을 점유하는 점을 감안해 여유를 권한다.[1]

## 저자의 해석 (분석·주장 부분)

- "VRAM 중심 → DRAM 중심" 패러다임 전환: GPU 9종 전수 결과 저용량 VRAM 카드(3060·3080 Ti·5070)와 16GB 카드(5070 Ti·5080)가 실사용 목록에 들어왔고, 3080 Ti·3060의 중고 가성비 재평가까지 언급했다.[1]
- 확장성 관점: 고가 GPU 증설보다 DDR5 메모리 증설(64GB 약 100만 원대)이 접근성이 낫다고 비교.[1]
- 향후 기대: Qwen 4(QM4로 표기)가 같은 N-gram 임베딩 아키텍처라면 DRAM 한도 내에서 모델 규모를 더 키울 수 있을 것으로 기대. 단 "개발자 지원 여부에 달려 있다"는 단서를 붙임.[1]
- 저자의 사용 전략: OpenCode는 무료 Muse Spark 모델로 세팅·측정에만 쓰고, 로컬 모델은 Hermes 등 에이전트에 OpenAI 호환 URL로 연동해 사용. Strata 웹 UI(IP:포트)에서 챗·모니터링(GPU 온도, 초당 토큰) 확인 가능.[1]

## 공식 자료 교차 확인 (2026-10-09 기준)

영상 발언과 별개로 다음 출처를 확인했다.

- **모델**: QwenLM 공식 저장소에 따르면 Qwen3.8-Flash-Next는 125B 메인 모델 + 51B N-gram 임베딩, 토큰당 6B 활성화 멀티모달 MoE이며, N-gram 임베딩 테이블을 호스트 메모리에 오프로드하고 연산과 겹치는 prefetch를 공식 설계로 명시한다. "Qwen4 아키텍처의 조기 미리보기"라는 표기도 공식 문서에 있다.[2]
- **Strata**: GitHub `Niko1221/Strata`(MIT 라이선스, 2026-09-24 생성). 12GB 이상 GPU + 32GB 이상 RAM + 80GB 이상 저장공간 요구, Windows/Linux 지원, localhost의 OpenAI/Anthropic 호환 API, AI 어시스턴트에게 설치를 맡기는 `AI_SETUP.md`, 멀티 GPU 문서가 존재. 공식 벤치마크는 RTX 5070(12GB)+64GB RAM에서 Q2_0 94토큰/초, IQ3_S 53토큰/초 등 영상 수치와 같은 규모.[3]
- **모델 변형**: Coder는 전문가 절반 제거 변형으로 "저자 측정 SWE-bench Verified 91%", CJK 약함; Unsloth UD-Q4_K_XL은 64GB PC에서 SSD 스트리밍으로 7~8.5토큰/초로 급락 — 영상의 "4비트가 반드시 빠르진 않다, PCI 레인 병목" 설명과 부합.[3]
- **독립 검증 경고**: Tessera 기사는 Strata의 신규성을 "아키텍처가 아니라 패키징(인스톨러·양자화 기본값·API·MCP)"으로 평가하고, 3090 100~140토큰/초는 **미측정 예측**이며 Coder의 91% 수치는 외부 벤치마크가 아니라고 지적한다.[4]

## 실무 채택 기준과 한계

- 채택 기준(영상+공식 문서 종합): ① MoE+N-gram 계열 모델만 대상, ② VRAM 12GB 이상보다 **DRAM 용량으로 모델 등급 결정**(32GB→Coder, 48GB→IQ2_XS, 64GB→IQ3_XXS, 96GB+→IQ3_S/4비트), ③ NVMe SSD 권장, ④ 듀얼 GPU는 레이어 분할 옵션(예: 24+24)을 명시해야 이득.
- 한계: ① 순정이 아닌 커뮤니티 양자화 모델 — 지능 저하는 영상에서 측정되지 않았고 저자도 "리눅스 체감 테스트 예정"이라 밝힘, ② 속도 수치는 저자 단일 환경 측정으로 재현성 미검증, ③ 4비트 이상 고밀도는 DRAM 초과 시 SSD 스트리밍으로 10배 이상 느려짐, ④ PCI 레인·메모리 대역폭 영향은 정량 분리되지 않음, ⑤ Windows 지원은 확인됐으나 AMD 이미지 입력 등 세부 기능은 플랫폼 제한.[1][3][4]

## 에이전트 활용 관점 (이 프로젝트와의 연결)

- Strata는 OpenAI/Anthropic 호환 엔드포인트와 MCP 서버를 제공해 Claude Code, Codex CLI, OpenCode, Hermes 같은 코딩 에이전트를 **비용 없는 로컬 모델**로 구동하는 수단이다. 영상은 OpenCode로 설치·측정을 위임하고 Hermes에 연동하는 흐름을 보여준다.[1][3]
- `03-에이전트-설정`의 관점에서는 "설치·세팅·성능 측정 절차 자체를 에이전트에게 위임하는 실무 예"로, `01-AI-네이티브-SDLC`의 관점에서는 "코딩 에이전트의 로컬·온디바이스 배포 옵션"으로 연결된다. 에이전트에게 설치 권한(폴더 접근, 명령 실행)을 부여하는 사례이므로 가드레일 관점의 검토 대상이다.
