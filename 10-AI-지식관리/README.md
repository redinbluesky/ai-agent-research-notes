# AI 지식관리

AI Second Brain, Obsidian, LLM 위키를 중심으로 개인의 자료와 생각을 축적하고 다시 활용하는 방법을 정리한다. 설치 명령이나 복잡한 시스템 설계보다 **개념과 역할, 작게 시작하는 활용 흐름**에 초점을 둔다.

## AI Second Brain을 한 문장으로

**내가 읽은 자료와 내 생각을 외부에 기록해 두고, AI의 도움으로 찾아 연결하고 다시 사용하는 개인 지식 시스템**이다. 여기서는 특정 제품 이름이 아니라 이러한 활용 방식을 가리키는 말로 사용한다.

- 메모는 기록을 남기는 것이다.
- Second Brain은 기록을 연결하고 필요할 때 다시 활용하는 것이다.
- AI Second Brain은 그 과정의 검색·요약·정리·비교를 AI가 돕는 것이다.

중요한 것은 자료의 양이 아니라 **필요한 질문에 근거 있는 답을 얻고, 실제 결과물에 다시 쓸 수 있는가**다. 이는 아래 영상들을 바탕으로 한 이 문서의 종합 관점이다.

## 각 도구의 역할

| 구성 | 쉬운 설명 | 맡기는 일 |
|---|---|---|
| **Obsidian** | 지식을 보관하고 읽는 노트 공간 | 로컬 Markdown 저장, 노트 연결, 검색과 시각화.[1][12] |
| **Hermes 등 AI 에이전트** | 노트를 읽고 정리하는 조수 | 허용된 파일을 읽어 요약·비교하고 기존 문서와 목차를 갱신.[2] |
| **LLM 위키** | AI가 지속적으로 관리하는 지식 정리 방식 | 원본과 정리된 지식, 운영 규칙을 구분해 축적.[8] |
| **Graphify** | 자료의 개념과 관계를 뽑아 만든 탐색 지도 | 자료가 많을 때 참고용 지식 그래프를 생성하고 Obsidian 노트로 내보내기.[3][9][11] |
| **사람** | 무엇을 남기고 어떻게 해석할지 결정하는 주체 | 자료 선정, 자신의 관점 기록, 중요한 사실 확인과 최종 판단 |

**Obsidian 자체가 AI는 아니며, Graphify도 필수 구성은 아니다.** 영상의 기본 조합은 동일한 노트 폴더를 Obsidian과 에이전트가 함께 사용하는 방식이다.[2]

## LLM 위키: 대화가 끝나도 정리된 지식을 남긴다

Karpathy의 LLM Wiki 원문은 질문할 때마다 원본에서 답을 만드는 것에 더해, AI가 중간 결과인 Markdown 위키를 계속 만들고 갱신하는 방식을 제안한다.[8]

| 구분 | 담는 내용 | 관리 원칙 |
|---|---|---|
| 원본 자료 | 기사, 논문, 영상 근거, 수집한 문서 | 출처를 유지하고 원본을 임의 수정하지 않는다 |
| 정리된 지식 | 개념 설명, 비교, 요약, 관련 문서 링크 | 새 자료와 검토 결과를 반영해 갱신한다 |
| 운영 규칙 | 정리 방식, 출처 표기, 수정 범위, 점검 절차 | AI가 일관되게 작업하도록 명시한다 |

이 구분은 원문의 세 계층을 쉽게 풀어 쓴 것이다. 반드시 같은 이름의 폴더 세 개를 만들어야 한다는 뜻은 아니다.[8]

운영은 **자료 넣기(Ingest) → 질문·활용(Query) → 모순·누락 점검(Lint)**을 반복한다. 좋은 비교나 분석 답변은 검토한 뒤 다시 문서로 남긴다.[8]

## 간단한 활용 흐름 — 이 프로젝트에 대한 제안

1. **기존 Markdown 프로젝트를 Obsidian에서 연다.** 기존 주제별 폴더와 README를 그대로 유지한다. 별도 복사본부터 만들 필요는 없다.
2. **작은 질문 하나를 정한다.** 예: “내가 모은 자료에서 Claude와 Codex를 추천하는 조건은 어떻게 다른가?”
3. **자료를 넣고 출처와 생각을 함께 남긴다.** “왜 저장했는가”, “동의하거나 의심하는 부분은 무엇인가” 정도면 충분하다.
4. **AI에게 기존 지식과 비교하도록 요청한다.** 새 사례를 정리하고, 중복되는 일반 원칙은 기존 주제 README에 반영하도록 한다.
5. **결과를 실제 작업에 쓴다.** 비교표, 도입 검토 메모, 발표 초안 등에 활용하고 근거 문서를 연결한다.
6. **주기적으로 점검한다.** 깨진 링크, 오래된 주장, 출처 없는 요약, 서로 모순되는 설명을 확인한다.

예시 요청:

> 이 자료를 요약하고 기존 관련 문서와 공통점·차이점을 비교해 줘. 출처 사실, 내 의견, AI의 해석을 구분하고, 근거가 부족한 부분은 표시해 줘. 기존 문서를 바꿀 때는 변경 범위를 먼저 알려줘.

현재 저장소의 `사례/`는 **원본 그 자체가 아니라 출처별 분석 문서**다. 영상 추출 원본·중간 자료는 기존 도구의 로컬 `결과/`에 유지한다. 이 구분을 유지하면 영상의 영문 폴더 구조를 그대로 복제하지 않아도 된다.

## Graphify는 언제 추가할까?

세 번째 영상은 내 관점이 담긴 핵심 위키와 자동 추출한 참고층을 분리하는 방식을 제안한다. `graph_imports`는 그 영상에서 선택한 참고층 폴더명이지 모든 지식관리 시스템의 필수 규격은 아니다.[3]

| 구분 | Obsidian 그래프 뷰 | Graphify |
|---|---|---|
| 무엇을 보여 주나? | 노트 사이에 이미 존재하는 링크.[4] | 자료에서 추출한 개념·구조·관계.[9] |
| 주된 용도 | 내가 만든 지식 연결을 살펴보기 | 여러 자료의 관계를 탐색하고 원문으로 접근하기 |
| 주의점 | 선이 많다고 지식의 품질이 높은 것은 아님 | 추론된 관계는 사실 확인이 필요함 |

**추천:** 먼저 Obsidian과 AI의 기본 흐름만 사용한다. 자료를 찾거나 연결하는 데 실제 어려움이 생기면 Graphify를 별도 참고층으로 시험한다. 같은 질문에 대해 기존 검색보다 근거를 잘 찾는지, 구축·갱신 비용까지 포함해 이점이 있는지를 보고 채택한다.

## 운영 사례에서 보완한 공통 원칙

두 인터뷰에서 가져올 핵심은 더 많은 도구가 아니라 **기록의 목적과 책임을 분명히 하는 것**이다.[13][14]

- **저장 이유를 남긴다.** “왜 모았나, 내 생각은 무엇인가, 어디에 쓸 것인가”를 짧게 기록한다.
- **사람의 판단과 AI 초안을 구분한다.** 볼트 분리는 한 방법이지만 필수는 아니다. 먼저 작성 주체·출처·검토 상태를 구분한다.
- **전체를 기억하기보다 찾는 길을 만든다.** README·문서 설명·관련 작업 링크를 통해 필요한 지식과 실제 산출물로 이동하게 한다.
- **작업 로그를 다음 시작점으로 쓴다.** 대화 전문을 무조건 쌓기보다 결정·근거·미완료 항목을 남긴다.
- **자동화보다 재사용을 확인한다.** 노트 수·그래프 크기·평가 점수보다 실제 판단과 결과물에 도움이 되는지를 본다.

이 목록은 인터뷰를 현재 프로젝트에 맞게 종합한 제안이다. 상시 녹음·화면 기록이나 다수 에이전트 구축은 입문 요건이 아니며 이번에 도입하지 않는다.

### RAG와 LLM 위키는 양자택일이 아니다

RAG는 외부 근거를 찾아 답변에 쓰는 방식이고, LLM 위키는 정리된 지식을 지속적으로 만들고 갱신하는 방식이다. 위키를 검색하는 시스템으로 함께 사용할 수 있으며, CMDS 공개 위키도 검색 도구를 병행한다고 설명한다.[8][18]

**“RAG는 새 문서마다 전체 재색인이 필요하다”는 일반화는 부정확하다.** Azure AI Search 공식 문서는 문서별 증분 추가·수정·삭제를 지원한다.[15] 따라서 위키의 가치는 RAG의 대체 여부보다, 사람이 읽고 검토할 수 있는 지식과 연결을 얼마나 잘 축적하는지로 판단한다.

## 오해하지 말아야 할 점

- **외부 기억이지 무제한 기억이 아니다.** 파일에 남겼어도 AI가 필요한 문서를 찾고 읽지 못하면 답에 반영되지 않는다.
- **지식 축적은 모델 재학습과 다르다.** 이 방식의 핵심은 모델 자체를 훈련하는 것이 아니라 외부 문서를 갱신해 다시 읽는 것이다.[8]
- **많이 쌓인다고 자동으로 정확해지지 않는다.** 잘못된 요약과 오래된 정보도 누적될 수 있으므로 사람의 검토가 필요하다.
- **로컬 저장과 외부 전송은 별개다.** Obsidian 파일이 로컬에 있어도 연결한 AI가 읽는 내용은 해당 서비스로 전달될 수 있다.
- **무료 도구가 무료 AI 처리를 뜻하지 않는다.** Graphify의 코드 구조 추출과 달리 문서·이미지의 의미 추출에는 LLM 토큰 비용이 들 수 있다.[9]
- **생성된 답변은 새로운 독립 출처가 아니다.** 다시 저장할 때도 원출처와 AI 분석이라는 구분을 유지한다.

## 범위와 확인 수준

지정된 로컬 유튜브 분석 도구로 다섯 영상의 메타데이터·한국어 자동 자막을 확보하고, 설명란·챕터 및 관련 1차 문서와 대조했다. 자동 자막의 고유명사·명령어에는 오류 가능성이 있다. 화면을 직접 재생해 확인한 분석은 아니며, 도구 설치·영상 속 워크플로 재현·AKM 평가 실행과 결과 제출은 수행하지 않았다.

이 폴더는 지식관리 개념과 활용 연구를 다룬다. 에이전트의 일반 설정은 [03-에이전트-설정](../03-에이전트-설정/), 기업 업무 운영은 [08-에이전트-업무적용](../08-에이전트-업무적용/)과 구분한다.
