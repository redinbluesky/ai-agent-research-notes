## 한 문장 결론

Jev는 글을 생성하는 LLM을 대체하기보다, 상태를 Choice·Score·Noul 같은 고정된 판단으로 바꾸어 라우팅·분류·점수화·검토 분기에 넣는 빠른 자동화 레이어로 사용하는 것이 적합하다.[1][2][3]

## 문제와 제안된 메커니즘

영상은 기존 생성형 LLM이 긴 텍스트를 만들고 수 초간 추론하는 데 비해, Jev는 주어진 상태에서 필요한 짧은 판단을 구조화된 값으로 반환한다고 설명한다.[1] TypeSafe도 Jev를 문자열 대신 기계가 처리할 수 있는 typed decision과 confidence를 반환하는 System One 모델로 소개한다.[2]

Jev API의 요청에는 판단할 `state`와 이름을 사용자가 정한 `questions` 맵이 들어간다. 응답은 같은 질문 ID 아래에 하나씩 반환되므로, 애플리케이션 코드는 텍스트를 다시 파싱하지 않고 후속 분기를 실행할 수 있다.[3][5]

| Primitive | 적합한 질문 | 반환값 | 영상의 대응 사례 |
|---|---|---|---|
| Choice | 고정된 보기 중 어디에 속하는가? | 선택값, 보기별 확률, confidence | 고객 문의 담당 팀, 모델·도구 라우팅, 콘텐츠 분류 |
| Score | 정의한 순서형 기준에서 어느 수준인가? | 확률 가중 점수, 등급별 확률, confidence | 리뷰의 청결·소음·위치 평가, 리드·위험 점수 |
| Noul | 특정 문장이 참인가? | 참일 확률(0~1) | 긴급성, 스팸 여부, 검토 필요성 판단 |

Choice·Score·Noul의 반환 형식과 한 요청에서 여러 질문을 함께 평가하는 방식은 공식 Quick Start와 API 문서에 명시되어 있다.[3][5]

Choice는 최대 255개 선택지를 받을 수 있고, Score는 2~10개의 순서형 등급을 받는다.[4][5]

## 영상이 제시한 활용 사례

### 1. 스위치 — 모델·도구 라우팅

영상은 요청마다 저비용 모델, 고성능 모델, 또는 다른 도구로 보내는 결정을 Jev가 앞단에서 맡는 구성을 제안한다.[1] 이는 Choice로 "simple-model", "frontier-model", "human-review"처럼 사전에 정한 경로를 고르는 패턴으로 구현할 수 있다.[4]

단, 이 판단은 모델의 장기적 품질을 종합 평가하는 심사 역할이 아니라, 운영자가 미리 정의한 난이도·위험도·비용 기준에 따라 요청을 분류하는 역할로 제한해야 한다.[1][4]

### 2. 필터와 대량 처리

지원 티켓, 댓글, 리뷰처럼 사람이 모두 읽기 어려운 텍스트에서 담당 팀, 긴급성, 정서, 정책 위반 가능성을 병렬로 평가하는 용도는 Jev의 API 구조와 맞는다.[1][3] 공식 문서는 모든 Choice 질문을 하나의 요청에 넣고, 확률을 함께 사용하며, 선택지에 `other` 또는 `none of the above`를 포함하라고 권고한다.[4]

영상의 호텔 리뷰 분석처럼 대량 데이터에 점수를 붙일 때는, 점수의 의미를 "측정값"으로 오해하지 말고 정해 둔 rubric에 대한 확률 가중 판단으로 해석해야 한다.[1][5]

### 3. 실시간 개인화와 컷 편집

영상은 유입 경로·클릭·체류 시간으로 UI 구성 요소를 고르거나, 무음 구간의 영상 편집 지점을 판단하는 실시간 반응 사례를 든다.[1] 저지연 구조화 판단은 이 같은 워크플로의 구성 요소가 될 수 있지만, 전환율 향상이나 개인화 품질은 별도 A/B 테스트로 검증해야 한다.[1][2]

방문자 행동 데이터를 쓸 때는 동의, 최소 수집, 보관 기간, 민감 속성의 간접 추론, 차별적 결과를 별도 설계 대상으로 둔다.[1] 사용자가 AI 판단을 인지하지 못하더라도 개인정보·정책 책임은 사라지지 않는다.[1]

## 공식 자료 교차 확인과 한계

### 속도·비용 수치는 공급자 기준이다

TypeSafe는 System One 작업 워크플로에서 193.6배 빠르고 444.6배 저렴하다는 수치를 제시한다.[2] 이 수치는 회사가 선택한 작업·기준 모델·입력 조건의 비교이므로, 글쓰기·코딩·장기 계획 등 모든 생성형 AI 작업에서의 일반 성능이나 비용 절감으로 확대 해석하면 안 된다.[1][2]

### 구조화된 출력은 환각 0%를 뜻하지 않는다

공식 사이트는 typed decision과 calibrated confidence를 강조하지만, API가 정해진 선택지 중 하나만 반환한다는 사실은 그 선택이 의미상 정확하다는 보장이 아니다.[2][5] TypeSafe의 Agent Skill 문서도 잘못된 질문·threshold가 false positive 또는 false negative를 만들 수 있다고 안내한다.[6]

특히 Noul은 별도 confidence가 아니라 참일 확률만 반환한다. Choice·Score의 confidence와 같은 방식으로 처리하지 말고, 각 질문 유형의 확률·confidence 의미를 분리해 정책을 설계해야 한다.[3][5]

### 이미지 의미 검색은 영상의 미래 가정이다

영상은 이미지 입력 지원이 추가되면 의미 기반 이미지 인덱싱이 가능할 것이라고 전망한다.[1] 현재 확인한 공식 API 문서는 `state`를 문자열·객체·배열로 정의하며, 이 사례에서는 이미지 입력 지원을 확인하지 못했다.[5] 따라서 이미지 기반 검색은 확인된 현재 기능이 아니라 영상의 전망으로 기록한다.

## 도입 기준과 안전한 자동화 패턴

다음은 영상의 추천을 일반화한 것이 아니라, 공식 API 구조를 바탕으로 한 연구자의 적용 제안이다.

1. **판단을 작게 자른다.** "이 코드는 좋은가?"처럼 열린 질문이 아니라 "이 요청은 고위험 변경인가?"처럼 관측 가능한 신호와 유한한 결과를 가진 질문을 만든다.[1][5]
2. **선택지의 탈출 경로를 둔다.** Choice에는 `other`, `unknown`, `human-review`를 두어 분류 체계 밖의 입력을 강제로 처리하지 않는다.[4]
3. **질문·기준·임계값을 한곳에서 관리한다.** TypeSafe는 사람이 질문과 threshold 상수를 검토하기 쉽게 모으라고 권고한다.[6]
4. **자동 처리와 검토를 분리한다.** 사전에 라벨링한 표본으로 precision·recall, 오탐·미탐 비용, confidence 구간별 정확도를 측정한 뒤에만 자동화 범위를 넓힌다.[2][6]
5. **장애 경로를 구현한다.** API의 429·529 응답에는 지수 백오프 재시도가 필요하며, 재시도 실패 시 보류·사람 검토·기존 규칙 기반 경로를 준비한다.[5]
6. **고위험 최종 판단에는 쓰지 않는다.** 채용, 신용, 보험, 의료, 법률, 징계처럼 개인에게 중대한 영향을 주는 결론은 모델 점수만으로 자동 실행하지 않는다.[1]

## 에이전트 설정과의 연결

TypeSafe는 Claude Code 플러그인 또는 다른 에이전트용 Skills CLI를 통해 공식 Agent Skill을 설치하는 방법을 제공한다.[3][6] 이 스킬은 API 요청·응답 형태와 설계 패턴을 코딩 에이전트에 제공할 수 있지만, 실제 설치 전 다음을 확인해야 한다.

- API 키는 코드나 지침 파일이 아니라 환경 변수 등 비밀 관리 경로에 보관한다.
- 플러그인 설치 범위가 프로젝트 로컬인지 전역인지와 자동 업데이트 여부를 확인한다.[6]
- 에이전트가 만든 질문·선택지·threshold는 코드 리뷰와 평가 데이터 검증을 거친다.
