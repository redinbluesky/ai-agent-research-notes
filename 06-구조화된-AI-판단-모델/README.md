# 구조화된 AI 판단 모델

자유 형식 텍스트를 생성하는 대신, 주어진 상태를 고정된 선택·점수·확률로 평가해 소프트웨어가 바로 실행할 수 있는 결과를 내는 AI 모델과 API를 정리한다.

## 다루는 범위

- Choice·Score·참/거짓 확률처럼 타입이 정해진 판단 결과
- 모델·도구 라우팅, 대량 분류, 위험 점수화, 자동 처리와 사람 검토의 분기
- 확률·confidence·임계값을 이용한 불확실성 관리
- 질문·선택지·등급 기준의 버전 관리, 평가 데이터, 오류·재시도, 개인정보·공정성 검토

## 핵심 원칙

1. **스키마 제약과 의미 정확성을 구분한다.** 정해진 값만 반환해도, 그 값이 의미상 옳다는 보장은 없다.
2. **질문·기준·임계값을 정책으로 관리한다.** 코드 곳곳에 흩어 두지 말고 한곳에 모아 리뷰·변경·롤백 가능하게 한다.
3. **고신뢰 자동화에도 검토 경로를 둔다.** `other`, 사람 검토 큐, 재시도·장애 대응을 포함한다.
4. **정확도만 보지 않는다.** 오탐·미탐 비용, 자동 처리율, 검토율, 지연, 비용, 집단별 편향을 함께 측정한다.
5. **긴 추론·고위험 최종 결정을 위임하지 않는다.** 구조화된 빠른 판단은 열린 문제 해결이나 법적·의료적·인사적 최종 판단을 대체하지 않는다.

## 다른 주제와의 연결

- `02-에이전트-친화적-웹`: 개인화 UI와 웹 기능의 상태 변경을 판단할 때 안전한 분기·권한·감사 설계가 필요하다.
- `03-에이전트-설정`: 코딩 에이전트가 판단 API를 통합할 때 스킬·환경 변수·권한 범위를 관리한다.
- `05-에이전트-네이티브-도구`: 에이전트가 직접 조작하는 도구에 판단 모델을 조합할 수 있으나, 이 주제는 도구 자체보다 판단 API와 자동화 정책에 초점을 둔다.

## 자료 추가 기준

- 사례 파일명은 루트 [AGENTS.md](../AGENTS.md)의 명명 규칙을 사용한다.
- 생성형 모델 대비 속도·비용 수치는 작업 유형, 입력 크기, 기준 모델, 측정 환경을 함께 기록하고 공급자 주장과 독립 측정을 구분한다.
- 입력 상태, 질문·선택지·등급, confidence·확률의 의미, 자동화 임계값, 사람 검토·오류 처리 경로를 확인한다.
- 개인 데이터·민감 속성·고위험 판단을 다룰 때는 동의, 최소 수집, 보관, 편향, 이의 제기·재검토 절차를 함께 검토한다.
