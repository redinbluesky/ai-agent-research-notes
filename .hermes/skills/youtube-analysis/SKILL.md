# 유튜브 분석

이 프로젝트의 `99-도구/01-유튜브-분석/유튜브_분석.py`를 표준 추출기로 사용한다. 외부 자막 API를 우선 도입하지 말고, 기존 도구가 생성하는 메타데이터·챕터·정리 자막·분석 입력 자료를 근거로 분석한다.

## 사용 시점

- YouTube URL 또는 11자 영상 ID의 내용 분석, 요약, 챕터화, 사례 문서화를 요청받았을 때
- 자막과 영상 메타데이터를 함께 수집해 근거 기반의 한국어 리서치 노트를 만들 때
- 기존 `결과/<영상-ID>/분석-입력자료.md`를 분석 입력으로 활용할 때

다음에는 사용하지 않는다.

- 영상 파일·오디오 다운로드 요청: 이 도구는 자막과 메타데이터만 수집한다.
- 비공개·삭제·로그인·연령 제한 영상의 우회 접근 요청
- 이미 충분한 자막·메타데이터가 사용자에게 제공된 경우의 단순 요약

## 절차

1. **입력 검증** — URL 또는 11자 영상 ID를 확인한다. 분석 범위가 불명확하면 기본값으로 `핵심 주장·시연 근거·한계·실무 적용점·타임스탬프별 개요`를 사용한다.
2. **추출** — `terminal`에서 프로젝트 루트를 기준으로 다음을 실행한다.

   ```bash
   cd "99-도구/01-유튜브-분석" && uv run 유튜브_분석.py "<YouTube-URL-또는-영상-ID>"
   ```

   완료 기준: `결과/<영상-ID>/분석-입력자료.md`가 생성되고 비어 있지 않다. 자막이 없으면 `자막-추출-오류.txt`를 읽고, 메타데이터와 챕터만으로 분석 가능한 범위를 명시한다.
3. **근거 확인** — `read_file`로 `분석-입력자료.md`, `챕터.md`, `메타데이터.json`을 읽는다. 영상에서 말한 내용, 공식 문서로 교차 검증한 사실, 분석자의 해석·제안을 분리한다. 기술 제품·표준의 최신 상태는 `web_extract` 또는 `web_search`로 공식 문서를 확인한다.
4. **분석 작성** — 다음 순서로 한국어 초안을 만든다.
   1. 한 문장 결론
   2. 영상 정보와 출처
   3. 핵심 주장과 영상 내 근거
   4. 구현·작동 방식 또는 시연 분석
   5. 공식 문서 교차 검증
   6. 한계·위험·도입 기준
   7. 실무 적용점
   8. 타임스탬프별 개요와 출처
5. **저장 전 승인** — 최종 사례 문서는 연구 주제의 `사례/`에 `YYYY-MM-DD-출처-주제.md` 형식으로 저장한다. 새 문서 생성·기존 문서 변경 전에 대상 주제와 경로를 사용자에게 제안하고 승인받는다. 추출 중 생성된 `결과/` 산출물은 로컬 분석 입력이며 최종 연구 문서로 취급하지 않는다.

## 결과 파일

```text
99-도구/01-유튜브-분석/결과/<영상-ID>/
├─ 메타데이터.json
├─ 챕터.md
├─ 자막-원본.ko.vtt 또는 자막-원본.en.vtt
├─ 자막-정리본.md
└─ 분석-입력자료.md
```

## 주의 사항

- 한국어 자동 자막을 우선하고, 없을 때만 영어 자막을 사용한다. 실제 확보된 자막 언어를 결과에 밝혀야 한다.
- 자동 자막은 오인식·누락 가능성이 있으므로 인용과 기술 주장에는 타임스탬프를 붙이고, 핵심 기술 사실은 1차 출처로 교차 검증한다.
- 자막이 없다는 사실은 영상의 주장을 검증하지 못했다는 뜻이 아니다. 분석 가능한 근거 범위를 구분해 쓴다.
- 영상에 연결된 구현 저장소는 설명만으로 신뢰하지 않는다. 필요하면 라이선스, 권한, 실제 구현, 테스트를 별도로 점검한다.
- `결과/`, 가상환경, 캐시, 원본 자막은 연구 노트의 최종 산출물에 포함하거나 커밋하지 않는다.

## 검증

- 추출 뒤 `분석-입력자료.md`가 비어 있지 않은지 확인한다.
- 분석 문서에는 URL, 채널/게시자, 게시일(확인 가능 시), 영상 길이, 타임스탬프, 공식 출처를 기록한다.
- 영상 내 주장·외부에서 검증한 사실·분석 의견이 서로 구분되어야 한다.
