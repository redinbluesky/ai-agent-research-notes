## 핵심 요약

영상은 `CLAUDE.md`에 모든 규칙과 절차를 누적하기보다 성격에 따라 분리하고, 항상 필요한 프로젝트 문맥만 남기라고 제안한다.[1]

## 출처의 내용

영상은 긴 `CLAUDE.md`에 모든 규칙을 누적하면 지침 준수에 불리하다고 설명하고, 다음 네 가지 분리를 권한다.[1]

| 영상의 분리 대상 | 제안한 역할 | 영상에서 든 예 |
|---|---|---|
| Rules | 한 주제의 규칙을 별도 파일로 옮기고 경로 조건을 지정 | 테스트 규칙, API 규칙 |
| Skills | 필요할 때 본문을 읽는 재사용 절차로 분리 | 배포 순서 |
| Hooks | 반드시 지킬 규칙을 자연어 부탁 대신 실행 제어로 처리 | 금지 동작 차단 |
| Agents | 출력이 긴 일을 별도 컨텍스트에 위임하고 요약을 받음 | 테스트 실행 |

분리 후 `CLAUDE.md`에는 프로젝트 소개와 자주 쓰는 명령어 등 항상 필요한 정보를 남긴다는 결론이다.[1]

이 영상은 역할 구분을 설명하는 짧은 안내 자료다. 자막·설명란만으로는 성능 개선량, 토큰 절감량 또는 차단 동작의 실험 결과를 확인할 수 없다. 그러므로 정량적 효과를 입증한 벤치마크로 해석하지 않는다.

## 이해를 위한 보충 사항

다음은 영상의 발언을 그대로 옮긴 내용이 아니라, 2026-10-07 확인한 공식 문서에 근거한 보충 설명이다.

- **200줄:** 각 `CLAUDE.md`를 200줄 미만으로 유지하라는 권고이지, 초과한 지침을 모두 무시하는 경계가 아니다.[2]
- **Rules:** 단순히 파일을 나누거나 본문에 경로를 적는 것이 아니라 `paths` frontmatter로 적용 경로를 지정한다. 경로 조건이 없는 규칙은 시작 시 로딩된다.[2]
- **Skills:** 기본적인 모델 호출 가능 스킬은 이름·설명을 미리 제공하고 호출 시 본문을 읽는다. 사용자 호출 전용 설정은 로딩 방식이 다르다.[3]
- **Hooks:** `.claude/hooks/`에 파일을 넣는 것만으로 활성화되지 않는다. 설정 등록과 이벤트·매칭 조건·검사 로직이 필요하다.[4]
- **Agents:** 별도 컨텍스트는 메인 대화의 중간 출력을 줄이는 데 유용하지만, 별도의 요청과 사용량이 발생한다.[5]
