# 에이전트 업무적용

AI 에이전트를 실제 기업 업무에 적용할 때 필요한 업무 재설계, 도메인 모델링, 실행 환경, 권한·승인, 검증·관측, 비용·성과 측정 방법을 정리한다. 단순한 챗봇·프롬프트 활용이 아니라, 에이전트가 제한된 업무 단위를 안전하게 실행하고 결과를 검증할 수 있는 운영 구조를 관심 범위로 둔다.

## 핵심 관점

1. **업무 단위부터 좁힌다.** 반복 빈도와 복구 가능성이 높고, 성공 조건을 측정할 수 있는 업무부터 자동화한다.
2. **도메인 지식을 실행 모델로 바꾼다.** 객체·상태·가능한 행동·예외·권한·승인 규칙을 구조화한다.
3. **프롬프트가 아니라 실행 환경을 설계한다.** 문맥, 도구, 진행 기록, 검증기, 재시도·중단·사람 이관 조건을 함께 둔다.
4. **완료 보고가 아닌 결과 상태를 검증한다.** 실제 시스템의 변경 결과, 정책 준수, 비용, 오류 복구 가능성을 평가한다.
5. **비용은 업무 성과와 함께 평가한다.** 토큰 수만이 아니라 완료 건당 추론비, 재작업·검토 비용, 품질, 처리 시간, 안전 지표를 함께 본다.

## 업무 적용 구조

```text
업무 목표·성공 기준
  → 도메인 객체·상태·정책 모델
    → 제한된 도구·권한·승인 경로
      → 에이전트 계획·실행
        → 실제 결과 상태 검증
          → 재시도 / 롤백 / 사람 이관
            → 감사 기록·평가·개선
```

## 다른 주제와의 연결

- `01-AI-네이티브-SDLC`: 개발 작업의 intent·spec·plan·테스트·배포 흐름을 다룬다. 이 주제는 그 원칙을 개발 외 기업 업무의 상태·권한·성과 책임까지 확장한다.
- `02-에이전트-친화적-웹`: 에이전트가 웹 기능을 안전하게 호출하는 인터페이스를 다룬다. 이 주제는 호출할 업무 행동과 승인·검증 정책을 정의한다.

- `05-에이전트-네이티브-도구`: 에이전트가 직접 조작할 도구와 인터페이스를 다룬다. 이 주제는 도구를 실제 업무 절차와 통제 구조에 연결하는 방법을 다룬다.
