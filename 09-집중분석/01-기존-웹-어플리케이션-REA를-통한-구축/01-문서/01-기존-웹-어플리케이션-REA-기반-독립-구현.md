# 기존 웹 어플리케이션 REA 기반 독립 구현

## 목적

기존 웹 어플리케이션을 Aside로 탐색하고, REA(Reverse Engineer Anything)로 관찰 근거를 수집한 뒤, Codex 또는 Claude Code로 **독립 구현**하는 흐름을 정리한다. 이 문서는 원본 코드·브랜드 자산·인증 우회·보호 기능의 복제가 아니라, 권한이 있는 대상의 기능적 요구사항을 분석해 별도 제품으로 구현하는 것을 전제로 한다.

## 결론

기술적으로는 가능하다. 다만 `Aside → REA → Codex 또는 Claude Code`가 원본 웹앱을 자동으로 복제하는 단일 경로는 아니다. 역할을 다음 네 단계로 분리해야 한다.

| 단계 | 도구 | 역할 | 핵심 산출물 |
|---|---|---|---|
| 탐색 | Aside | 허가된 계정·테스트 환경에서 사용자 흐름, 입력, 출력, 예외를 확인 | 사용자 흐름, 화면·상태 기록 |
| 관찰 | REA | 페이지 구조, 스크립트, 네트워크 관찰, 화면, 세션 변화를 Evidence와 함께 수집 | 관찰 근거와 한계 |
| 명세·구현 | Codex 또는 Claude Code | 관찰 사실을 기능 명세로 전환하고 목표 스택에 맞춰 독립 구현 | 요구사항, 코드, 테스트 |
| 비교 검증 | REA와 테스트 도구 | 동일 시나리오의 결과·상태·화면 차이를 확인하고 수정 | 검증 결과와 차이 목록 |

REA는 웹사이트를 대상으로 페이지 구조, 스크립트, 네트워크 관찰, 요청한 스크린샷 등을 분석 대상으로 제시하며, Codex와 Claude Code를 포함한 에이전트 연결을 지원한다.[1][2]

## 도구별 역할과 연결 방식

### Aside: 탐색·브라우저 작업 실행 계층

Aside는 웹사이트, 계정, 브라우징 컨텍스트를 이용해 브라우저 작업을 수행하는 AI 브라우저다. Claude Pro 또는 Max 구독을 Aside의 모델 제공자로 연결할 수 있고, CLI·MCP·REPL을 통한 외부 도구 연결도 제공한다.[3][4]

초기 단계에서는 Aside를 다음 용도로 제한하는 것이 적절하다.

- 테스트 계정으로 대상 기능을 실제 사용해 사용자 흐름을 작성한다.
- 입력값, 결과값, 오류 상태, URL 변화, 필요한 권한을 기록한다.
- 화면에서 확인할 수 있는 규칙과 예외를 수집한다.
- 결제, 주문, 외부 발송, 계정 변경, 개인정보 입력 같은 비가역 행동은 수행하지 않는다.

### REA: 수동적 관찰과 근거 수집 계층

REA의 웹 관찰은 사용자가 소유한 Chrome 계열 브라우저에 CDP로 연결해 기존 페이지의 제한된 Evidence를 수집하는 기능이다. 일반적인 브라우저 자동화 또는 원격 제어 기능이 아니며, 대상 코드의 실행·조작을 목적으로 하지 않는다.[5]

REA로 수집할 수 있는 대표 근거는 다음과 같다.

- DOM 구조와 접근성 노드
- 페이지가 로드한 스크립트·리소스와 정적 번들 관계
- 관찰 창 안의 SPA 이동, 리다이렉트, 오류, 수명주기 변화
- 제한된 네트워크·콘솔 메타데이터와 스크린샷
- 선택한 웹 스크립트의 정적 분석 결과와 소스맵 근거

REA 결과는 원본 소스 또는 기능 동등성의 증명이 아니다. 관찰 사실, 그에 따른 해석, 아직 확인하지 못한 범위를 구분해서 다음 구현 단계로 넘긴다.[5]

### Codex 또는 Claude Code: 독립 구현 계층

REA 설치·설정 문서는 Codex와 Claude Code를 포함한 선택 에이전트에 MCP 접근을 추가하는 흐름을 제공한다. 설정 전에는 변경 계획을 검토하고, 적용 뒤에는 대상 에이전트를 재시작해야 한다.[2]

Codex와 Claude Code 중 하나를 주 구현 에이전트로 선택하고, 다음 자료를 입력으로 제공한다.

1. 사용자 흐름 문서
2. REA Evidence와 관찰 범위·한계
3. 구현 대상의 기능 범위와 제외 범위
4. 목표 기술 스택과 데이터 모델
5. 테스트 시나리오 및 수용 기준

## 권장 구성

### 초기 검증 구성

```text
Aside
  └─ 허가된 대상 웹앱의 사용자 흐름 탐색
       └─ 사용자 흐름·입력·출력·예외 기록

별도 Chrome/Chromium 테스트 프로필
  └─ REA의 CDP 관찰
       └─ Evidence·스크립트·페이지 상태·화면 비교 자료 수집

Codex 또는 Claude Code
  └─ REA MCP 및 프로젝트 저장소
       └─ 명세화 → 독립 구현 → 테스트 작성 → 수정
```

REA의 공식 웹 관찰 문서는 Chrome 계열 브라우저의 CDP 연결을 전제로 한다.[5] 따라서 Aside의 현재 브라우저 세션을 REA가 직접 관찰할 수 있는지는 Aside가 외부 CDP 연결 또는 원격 디버깅을 지원하는지 별도로 검증해야 한다. 이 지원 여부가 확인되기 전에는 **Aside는 탐색용, 별도 Chrome/Chromium 프로필은 REA 관찰용**으로 분리하는 방식이 가장 안전하다.

### MCP 구성 원칙

- Aside 내부에서 Claude를 모델 제공자로 연결하는 일과, Codex·Claude Code에 Aside 또는 REA MCP를 등록하는 일은 별개의 구성이다.[3][4]
- 처음에는 주 구현 에이전트 하나에 REA MCP만 연결한다.
- Aside MCP는 실제 브라우저 조작이 필요한 범위가 명확하고, 계정·권한·승인 정책을 적용한 뒤 추가한다.
- 운영 계정이나 개인 브라우저 프로필 대신 테스트 계정과 분리된 프로필을 사용한다.

## 실행 절차

### 1. 범위와 권한을 먼저 확정

- 자사 서비스, 오픈소스 데모 또는 명시적 분석·재구현 허가가 있는 대상만 선정한다.
- 기능 단위로 범위를 정한다. 예: 상품 검색·필터·비교표 생성.
- 인증 우회, 접근 제어 우회, DRM 우회, 비공개 API 악용, 원본 자산 복제는 범위에서 제외한다.

### 2. Aside로 사용자 흐름 작성

다음 항목을 기능별로 기록한다.

| 항목 | 기록 예시 |
|---|---|
| 시작 조건 | 로그인 여부, URL, 선택된 탭 |
| 입력 | 검색어, 필터, 버튼 클릭, 파일 첨부 여부 |
| 화면 상태 | 로딩, 성공, 빈 결과, 오류, 권한 요청 |
| 출력 | 표, 카드, 정렬 순서, 다운로드, 메시지 |
| 예외 | 누락값, 네트워크 오류, 권한 부족 |
| 금지 행동 | 결제, 전송, 제출, 계정 변경 |

### 3. REA로 관찰 근거 수집

REA에는 기능 단위 질문을 전달한다. 예를 들어 다음과 같이 요청한다.

```text
허가된 테스트 환경의 검색 기능을 관찰해 줘.
확인된 DOM·스크립트·네트워크·화면 상태를 Evidence와 함께 제시해 줘.
관찰 사실, 기능에 대한 추론, 확인하지 못한 부분을 분리해 줘.
인증·접근 제어 우회나 상태 변경은 수행하지 마.
```

수집 결과에는 최소한 다음을 남긴다.

- 관찰 시각과 대상 URL
- 사용한 테스트 계정·브라우저 프로필의 식별 가능한 범위
- Evidence ID, 화면 또는 캡처물의 위치
- 확인 사실과 해석의 구분
- 누락·차단·관찰 불완전성

### 4. Codex 또는 Claude Code로 명세와 구현

에이전트에 전달할 요청은 관찰을 구현 명세로 바꾸는 데 초점을 둔다.

```text
다음 사용자 흐름과 REA Evidence를 바탕으로 기능 명세를 작성해 줘.

규칙:
- 관찰로 확인된 사실, 합리적 추론, 미확인 항목을 구분한다.
- 원본 코드, 브랜드 자산, 문구, 인증·접근 제어를 복제하지 않는다.
- 우리 제품의 기술 스택에 맞는 독립 구현안을 만든다.
- 구현 전에 API 계약, 화면 상태, 오류 처리, 테스트 시나리오를 먼저 작성한다.
- Evidence로 확인할 수 없는 동작은 추정 구현으로 표시한다.
```

### 5. 독립 테스트로 검증

- 원본과 동일한 입력을 기준으로 결과 형식, 정렬, 오류 처리, 상태 전이를 비교한다.
- 화면 유사성은 보조 지표로만 사용하고, 기능 수용 기준·접근성·성능·보안 테스트를 별도로 수행한다.
- REA의 비교 결과에서 누락·절단된 Evidence는 동등성의 증거로 취급하지 않는다.[5]

## Codex와 Claude Code 선택 기준

| 상황 | 우선 선택 |
|---|---|
| 기존 구현·테스트·저장소 작업이 Codex 중심 | Codex + REA MCP |
| 장기 계획과 코드베이스 탐색을 Claude Code 중심으로 운영 | Claude Code + REA MCP |
| Aside 창에서 브라우저 조사·표 작성 등 업무 작업을 직접 수행 | Aside 내부 Claude 연결 |
| 브라우저 탐색과 구현을 분리 | Aside는 탐색, Codex 또는 Claude Code는 REA Evidence 기반 구현 |

두 에이전트 중 무엇을 쓰더라도 핵심은 모델 선택보다 **근거가 있는 기능 명세와 독립 검증 루프**다.

## 안전·법적 경계

- REA의 MIT 라이선스는 분석 대상 웹앱, 계정, 데이터, 연결된 서비스에 대한 사용 권한을 부여하지 않는다.[1]
- 분석 또는 재구현은 자사 시스템, 오픈소스·공개 데모, 명시적 허가가 있는 대상에 한정한다.
- 운영 계정, 고객 데이터, 실제 결제 수단, 프로덕션 상태 변경은 초기 검증 범위에서 제외한다.
- 관찰한 비공개 데이터, 세션, 토큰, 자격 증명은 문서나 저장소에 기록하지 않는다.
- 구현 결과는 원본과 비슷해 보인다는 이유만으로 배포하지 않고, 별도 요구사항·보안·품질 기준으로 검증한다.
