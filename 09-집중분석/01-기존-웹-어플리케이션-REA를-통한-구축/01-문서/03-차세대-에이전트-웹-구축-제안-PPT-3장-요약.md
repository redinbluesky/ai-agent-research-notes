## 슬라이드 1. 낮에는 사람이 결정하고, 밤에는 에이전트가 구현·검증한다

**핵심 메시지: 기존 화면 복제가 아닌 업무 지식 복원과 차세대 재설계 — 비업무 시간까지 활용해 구축 대기 시간을 줄인다.**

### 슬라이드 본문

- **업무 지식 복원:** Aside로 사용자 흐름을 탐색하고 REA의 관찰 근거를 현업 규칙·예외·권한과 연결
- **야간 구현:** 승인된 작은 작업을 Codex·Claude Code가 격리 환경에서 구현·테스트·문서화
- **브라우저까지 검증:** Aside로 실제 클릭·입력·화면 이동·결과를 확인하고 API·데이터 검증과 결합
- **아침에는 근거로 판단:** 변경안·테스트 결과·미해결 사항을 사람이 검토 — 빠른 생성보다 검증된 진척

### 도식 문구

`기존 업무 관찰 → 업무 명세·사람 승인 → 야간 구현·브라우저 검증 → 다음 날 검토`

### 발표자 메모

OpenAI는 사람이 자는 동안에도 Codex가 한 작업을 6시간 이상 수행하는 사례를 보고한다.[1] Aside 공식 문서는 로컬 웹앱 스모크 테스트와 페이지 검사·스크린샷·브라우저 REPL을 안내한다.[8] 이를 결합한 운영은 본 프로젝트의 적용 제안이다. 야간 실행에는 작업·비용·재시도 상한과 실패 중단 조건을 둔다. 기본 결과물은 운영 자동 배포가 아니라 검토 가능한 변경안이다.

**표현 주의:** “완벽한 테스트”가 아니라 **“실제 사용자 흐름까지 확인하는 통합 검증”**이다. 보안·부하·접근성·다른 브라우저·백엔드 정합성은 별도 검사로 보완한다. 실제 결과 상태를 확인해야 하며 에이전트의 성공 보고만으로 완료하지 않는다.[6]

## 슬라이드 2. 담당자는 바뀌어도 지식은 남고, 유지보수는 이어진다

**핵심 메시지: 사람·에이전트가 같은 업무 지식과 검증 체계를 사용하여 인수인계 위험과 반복 조사 부담을 낮춘다.**

### 슬라이드 본문

- **공통 업무 규칙:** 사람 UI와 에이전트용 API·도구가 같은 서비스·권한·승인 기준 사용
- **지식의 자산화:** 명세·설계 이유·코드·테스트·운영 이력을 함께 관리하여 개인 기억과 대화 의존 감소
- **담당자 교체 위험 완화:** 신규 담당자와 에이전트가 같은 근거로 구조를 파악하고 오류·변경을 재현
- **SDLC 전반의 연속 지원:** 요구 변경 → 영향 분석 → 수정 → 회귀 테스트 → 배포 준비 → 운영 관측을 연결

### 도식 문구

`업무 지식 + 코드 + 테스트 + 운영 근거 = 담당자가 바뀌어도 재사용하는 유지보수 자산`

### 발표자 메모

OpenAI 사례는 저장소 지식의 버전 관리, 낡은 문서 수정 PR, 관측 정보를 활용한 진단·검증과 반복 정리 작업을 설명한다.[1] 담당자 교체 위험 감소는 이를 본 프로젝트에 적용한 기대 효과이며, 새 담당자의 환경 실행·오류 재현·첫 안전한 변경 과제로 측정한다.

WebMCP 같은 구조화된 인터페이스는 업무 실행의 해석 부담을 줄이는 후보지만, 유지보수성 자체를 보장하지 않는다.[3] 코드·명세·테스트·로그를 에이전트가 사용할 수 있어야 한다. 인수인계를 없애는 것이 아니라 검증 가능한 인수인계로 바꾸며, 현업 판단·운영 책임·고위험 승인은 사람이 맡는다.

## 슬라이드 3. 빨리 만드는 것을 넘어, 다음 변경을 안전하고 싸게 만든다

**핵심 메시지: Kent Beck의 변경 가능성 관점을 반영하여 속도·품질·미래 유지보수 비용을 함께 관리한다.**

### 슬라이드 본문

| 구현 원칙 | 실행 방식 | 기대 가치 |
|---|---|---|
| **사람이 반증할 수 있는 가독성** | 업무 경계·계약·코드·테스트·실행 근거 연결 | AI 설명을 맹신하지 않는 판단 |
| **미래 변경의 안전성과 비용** | 작은 구현 뒤 중복·결합·회귀·기술 부채 점검 | 재작업과 다음 변경 부담 완화 |
| **검증·되돌림에 맞춘 자율성** | 격리·독립 검증·승인·복구 경로에 따라 위임 | 통제 가능한 자동화 확대 |

### 하단 결론

**성과는 코드량이 아니라 검증된 업무 결과·변경 소요시간·회귀 결함·인수인계 부담·총비용으로 평가한다.**

`작은 파일럿 → 실제 브라우저·데이터 검증 → 기존 시스템과 단계적 전환 → 검증된 범위 확대`

### 발표자 메모

세 원칙은 [Kent Beck 발표에 관한 기존 분석](../../../01-AI-네이티브-SDLC/사례/2026-10-08-AgentOS-Kent-Beck-AI-시대-소프트웨어-공학.md)을 프로젝트 정책으로 적용한 것이며 발표자의 직접 인용문이 아니다. 핵심은 기능 사이에 멈춰 다음 변경의 선택지를 회복하는 것이다.

“AI로 개발 속도가 빨라졌다”만으로 생산성을 확정하지 않는다. 모델·실행 환경·사람 검토·실패 복구 비용까지 측정한다. 기존 업무의 점진적 교체는 Fowler의 레거시 현대화 접근을 참고한다.[4] 코드 롤백과 실제 데이터·외부 업무의 복구는 구분한다.
