## 1. 설계가 따르는 확정 결정

| 원본 관찰 사실 | 신규 설계 결정 (개선 — 원본 재현 아님) |
|---|---|
| 이미지 버튼·label 없는 입력 (O-002/O-003) | `<button>` 요소 + 연결된 `<label htmlFor>` (D1·D2 → A1·A2) |
| 상태가 hidden 필드(`strStep`)·display:none (O-003) | 데모 단계·오류·결과를 보이는 텍스트·`role="status"`로 노출 (D3) |
| 오류가 alert+전역변수 (O-003) | alert 금지, 항목별 인라인 오류 + `aria-describedby` (D4 → F4) |
| 중첩 table 레이아웃 (O-002) | `<header>/<nav>/<main>/<footer>` 시맨틱 구조, 레이아웃 table 금지 (D5) |
| 동적 form POST로 화면 전환 (O-003) | 클라이언트 라우팅 `/` → `/login`, 링크·라우터로 진입 (D6) |
| `form_login_info` 비활성 레거시 (O-004) | 재현하지 않음 (F2 확정) |
| `maxLength` 10/20 (O-003) | 채택 (D-007) — 경계값 테스트 필수 |
| `login.do` AJAX 인증 (O-003, 정적) | 구현 금지 (Non-goals) — 데모 안내로 대체 (F4) |

## 2. 화면 목록과 라우팅

| 경로 | 화면 | spec 요구 |
|---|---|---|
| `/` | 메인 | F1 (우측 상단 로그인 진입) |
| `/login` | 로그인 초기 (데모) | F1·F2·F4, 직접 진입·새로고침 유지, 뒤로 가기 → `/` |

라우팅 의존성(Vite 기본 제안에 맞춰 React Router)은 T0에서 승인·lockfile 고정 (plan §4).

## 3. 메인 (`/`) 구조

원본 관찰(O-002)으로 확인된 영역만 최소 재현 + 개선 배치:

- `AppHeader` — 사이트 이름 표시(원본 브랜드 자산 복제 금지), 좌측 `nav`(가상 메뉴 3~4개, 전부 `미구현` 안내 또는 비활성 — F3), 우측 상단 `<button>` "로그인" → `/login`으로 이동. 원본처럼 `img` 버튼·링크 아님.
- `MainContent` — `main` 요소. 가상 공지 목록(정적 데이터 `src/data/`), 각 항목은 텍스트. 범위 밖 항목 선택 시 `미구현` 영역 표시.
- `AppFooter` — 데모 표시 텍스트 (원본과 무관한 파일럿임을 명시 — F3).

원본의 중첩 table·GIF·배너 이미지는 재현하지 않는다(Non-goals: 자산 복제 금지).

## 4. 로그인 초기 (`/login`) 구조

원본 O-003의 **기능 요소**만 재현하고 **표현 결함**은 개선한다:

| 원본 (O-003) | 신규 컴포넌트 | 구현 방식 |
|---|---|---|
| `loginForm` POST 폼 | `LoginForm` (form, submit은 JS 처리) | `onSubmit` → 순수 검증 → 데모 안내. 네트워크 요청 없음 |
| `strUserId` text maxLength 10 | `TextInput` id="userId" + `<label htmlFor="userId">아이디</label>` | maxLength 10 (D-007) |
| `strPassWd` password maxLength 20 | `TextInput` id="password" + label "비밀번호" | maxLength 20,trim 변형 금지(spec §6) |
| 이미지 로그인 버튼 | `<button type="submit">로그인</button>` | 텍스트 버튼 |
| hidden `strStep`·`strOTP` | 재현 금지 | 데모는 인증 단계 없음 (Non-goals) |
| alert 오류 | `FieldError` | 항목 아래 인라인 + `aria-describedby`, `role="alert"` |
| (없던 것) | `DemoNotice` | "이 데모는 실제 인증을 수행하지 않습니다" 상시 표시 + `role="status"` |
| (없던 것) | 뒤로 가기 | `/` 복귀 (경계 사례 spec §6) |

검증 규칙 (F4·AC-F3):
1. ID 빈/공백뿐 → "아이디를 입력하세요" 오류. 비밀번호는 trim하지 않고 빈 값만 오류.
2. ID 10자 초과·비밀번호 20자 초과 입력 시도 → maxlength로 차단(경계 테스트: 10자 통과 / 11자 차단, 20/21 동일).
3. 유효 가상 입력 + 실행 → "실제 인증 미구현" 안내. 요청·저장·성공 화면 없음.
4. Enter·버튼 반복 → 동일한 데모 결과.

## 5. 상태·데이터 설계

- 화면 간·화면 내 상태는 React 지역 state만 (plan §2: 전역 라이브러리 금지).
- 검증은 순수 함수 `validateLogin(input): { userId?, password? }` — 단위 테스트 대상.
- 정적 가상 데이터 `src/data/demo.ts` (공지 목록, 데모 허용 계정 값 없음 — 입력 값 자체를 검증하고 어떤 값이든 "인증 미구현"으로 끝남 → 자격 증명 취급 회피).
- localStorage·sessionStorage·쿠키·URL 쿼리로 입력을 남기지 않음 (AC-S1).

## 6. 접근성·Aside 요구 연결 (A1·A2)

- 모든 인터랙션 요소는 role+이름으로 식별 가능: "로그인"(nav 버튼), "아이디", "비밀번호", "로그인"(submit 버튼). submit 버튼의 접근성 이름은 nav 버튼과 구분되도록 `aria-label="로그인 시도"` 제안.
- 포커스 순서: 헤더 → 메인 콘텐츠 → 로그인 진입. `/login` 이동 후 첫 입력으로 자동 포커스(화면 제목 `h1` "로그인").
- 오류 발생 시 오류 메시지를 입력과 연결, status 영역으로 낭독 가능하게.
- Aside AC-A1 검증 시나리오(추후): Aside 채팅으로 "로그인 화면 열어줘 → 아이디·비밀번호 입력 → 로그인 시도" 좌표 없이 수행 가능한지 확인.

## 8. 테스트 설계 (T0~T4 수용 기준 연결)

| 단위 | 대상 | 경계 사례 (spec §6) |
|---|---|---|
| 단위 | `validateLogin` | 빈·공백·10/11자·20/21자·trim 금지 |
| 컴포넌트 | `LoginPage` | 오류 표시·aria 연결·데모 안내·이중 submit 방지 |
| E2E | `/`→`/login` | 링크 진입, 직접 URL·새로고침 유지, 뒤로 가기 복귀 |
| E2E | 데모 흐름 | 가상 입력→"인증 미구현" 안내, 네트워크 요청 0건(네트워크 리스너로 확인) |
| 접근성 | axe 자동 검사 + 키보드 수동 | 라벨·포커스·name·역할 (AC-A2) |

## 9. 승인 체크포인트

이 문서 승인 후: T0 스캐폴딩(의존성 승인·lockfile) → T1 → T4 순서로 단위별 실행·검증(plan §3). 거절·수정 시 이 문서만 개정하고 스캐폴딩은 시작하지 않는다.
