이 파일은 질문·관찰·근거 대응·한계·설계 결정을 모으는 역설계 기록부다. Evidence 원본과 캡처는 `근거/`에 두고, 여기에는 근거 ID 또는 파일 위치만 인용한다. 관찰 사실 / 해석 / 미확인을 같은 항목 안에서 구분해 쓴다.

## 1. 허용 범위 (P0 승인 · 2026-10-20 사용자 동의)

| 항목 | 승인된 범위 |
|---|---|
| 관찰 대상 | `https://www.vaatz.com/vmp/main.do` → 우측 상단 **로그인 클릭** → 도달하는 **로그인 초기 화면**. 이 두 화면만 |

## 2. 기록 규칙

- 관찰 항목마다: 질문 ID, 대상 URL, 시각(UTC+9), 도구·모델, 프로필 역할, 재현 절차를 남긴다.
- 근거는 REA Evidence ID 또는 `근거/` 파일 위치로 인용하고, 정적 분석과 실행 관찰을 구분한다.
- 결정은 유지 / 개선 / 제외 / 추가 확인으로 분류하고 승인 상태를 적는다.
- 추적: RQ-n → 근거 또는 개선 결정 → 수용 기준(03.spec) → 테스트·검증 결과.
- 관찰 실패는 도구 연결 실패와 사이트 관찰 실패를 분리해 기록한다.

## 4. 관찰 로그

### O-000 · 2026-10-20 · REA 연결 확인 (P0)

- 도구: Hermes `mcp__rea__binary_session`
- 관찰 사실: 서버 `rea` 6.7.0 (package `rea-agents`, npx 캐시 설치) 정상 응답, MCP 도구 207·프롬프트 6 노출, 열린 분석 세션 없음. Windows 호스트에서 `native-macos` 프로바이더는 `unsupported_host`, `rea-artifact-graph`·`rea-dotnet-static` 사용 가능.
- 해석: Hermes–REA 역설계 경로가 실행 준비 완료. P1 착수 조건 충족.
- 근거: `binary_session` 응답의 `server_identity`·`capabilities` (세션 호출 결과)
- 한계: 이 항목은 도구 연결 확인일 뿐, VAATZ 대상에 대한 Evidence가 아니다.

### O-001 · P1 관찰 준비 — 격리 프로필·연결 경로 확인 (완료)

- 계획: REA의 브라우저 관찰 경로(`capture_browser_scenario`)로 격리된 세션에서 main.do 관찰. Aside 직접 연결은 검증된 경우에만 사용.
- 관찰 사실: `capture_browser_scenario`의 `mode:"launch"` + 청정 프로필(저장소 preseed 없음, headless)가 승인된 "격리 테스트 프로필" 요건을 만족. Aside CDP 연결은 시도하지 않았고 불필요함을 확인.
- 상태: 완료 — 이후 O-002·O-003에서 사용.

### O-002 · 2026-10-20 · 메인 화면(main.do) 관찰

- 도구·모델: `mcp__rea__capture_browser_scenario` (rea-playwright-browser-scenario v1) — Chrome 140 headless launch, 청정 프로필, viewport 1440×900, ko-KR/Asia/Seoul. 시각: 2026-10-20 (KST)
- 대상: `https://www.vaatz.com/vmp/main.do` (HTTP 200, DOM 33,138 bytes, title `VAATZ Marketplace`)
- Evidence: `ev_d85dc4e56116f2194ede718b0be9e017a74ed4208c316e86b97c64361641e311` — completeness complete, missing/truncated 없음
- 관찰 사실: SPA 프레임워크 없음 — 서버 렌더링 HTML + 중첩 `<table>` 레이아웃 + jQuery 1.9.1(vmp.js/common.js 등). 폼 4개(form_logout·form_for_move·form_login_info·form_common_popup)에 `REQ_PARAM_CALLBACK_FUNCTION`·`REQ_PARAM_RETURN_URL`·빈 `csrf` hidden 패턴. 로그인 진입 요소는 `<img id="btnLogin" alt="로그인" style="cursor:pointer">` — 인라인 onclick 없음(스크립트 bind). hidden iframe(hidden_iframe, about:blank) 1개.

- 한계: headless 1회, 상호작용 없음. 쿠키·네트워크 값 미보관.

### O-003 · 2026-10-20 · 로그인 클릭 → viewLogin.do 관찰

- 도구·모델: `mcp__rea__capture_browser_scenario` — main.do 로드 후 `click(css img#btnLogin)` → URL 전환 관찰. 입력·제출·다운로드 없음. 시각: 2026-10-20 (KST)
- 관찰 사실(전환): 클릭 후 `https://www.vaatz.com/vmp/common/login/viewLogin.do`로 이동(history navigation entry type=navigate). 메커니즘은 `jsLoginRedirect()` — 동적 POST 폼(`form_common_loginRedirect`, hidden `strRtnVoReset=Y`) 생성 후 `submit()`. 정적 GET 링크 아님.
- 관찰 사실(로그인 초기 화면): DOM 69,660 bytes. `loginForm` POST — 필드 `strUserId`(text, max 10), `strPassWd`(password, max 20, autocomplete=off), `strOTP`(max 6, display:none), hidden `strStep=0`·`REQ_PARAM_RETURN_URL=/main.do`·빈 `csrf`. 버튼이 전부 이미지(`btn_login`·`btn_pwOver`·`btn_OTP`[display:none])이고 jQuery bind로 `doLogin/doPwOver/doCreateOTP_POP` 연결. `doLogin()`은 `$.ajax POST /vmp/common/login/login.do`(strUserId·strPassWd·strStep·strOTP, header `res-protocol: json`) + 실패 시 alert. `hasOtpKey="N"` 서버 주입. Enter 키 → `doLogin`.
- Evidence: `ev_171a129f657b5384a532e952c120414861905a4786d411f1e0a0f6a887b2a45e` — completeness complete, page-error 1건(`closeWin is not defined` @ popupMasterOpen.do onunload, 메인 팝업 스크립트 결함 흔적)
- 접근성 관찰: 로그인 입력 textbox에 **label 이름 없음**(빈 이름), 이미지 버튼 alt 없음(`logingTable_item_*`), 영역 전체 table 중첩 → AX 트리가 구조를 거의 읽지 못함.
- 해석: 로그인 상태 단계(0→2=OTP)가 hidden 값 + display:none 토글로만 표현 — 에이전트가 화면 상태에서 인증 단계를 판단하기 어려움. 오류가 alert 문자열이라 구조화 관찰 불가.
- 상세: [근거/O-002-viewLogin-요약.md](근거/O-002-viewLogin-요약.md)
- 한계: 입력·인증 제출 금지 준수 → `login.do` 응답 스펙, csrf 값 주입 경로, OTP 표시 조건은 미확인(추가 관찰 없음).

### O-004 · 2026-10-20 · Aside 관찰 — `form_login_info` 실사용 여부와 main의 로그인 관련 요소 (RQ-4 미확인 해소)

- 도구: Aside CLI `aside.exe exec` → Aside 브라우저 에이전트 (프로필 `Profile 0` connected, 세션 `2026-10-20_ujmts5Xk1zEaXS18`). 지시: 이동·타이핑·클릭·다운로드·로그인 시도 금지, DOM·스크립트 텍스트 조회만.
- 관찰 사실:
  - `form#form_login_info`는 **hidden 2개(`REQ_PARAM_CALLBACK_FUNCTION`·`REQ_PARAM_RETURN_URL`)만 가진 폼**이고 text/password/submit 입력이 없으며, HTML·inline 스크립트·common.js·vmp.js·xtm.extUtils.js 어디에서도 참조·submit되지 않음 → **비활성(레거시) 마크업**. 이전 미확인("메인에서 직접 로그인에 쓰이는가") → **아니오로 해소**.
  - `#btnLogin` 클릭 핸들러의 실제 함수는 **`jsCallLoginPage`** — 동적 form(`form_common_btnLogin`, action `viewLogin.do`, hidden `strRtnVoReset=Y`) POST submit. **정정**: O-003에서 `jsLoginRedirect`로 기록한 것은 viewLogin 화면의 다른 버튼(`front_top_btn_2` 등)용 함수이며 main→로그인 경로와 무관함 (REA s2 DOM 재확인으로 확인).
  - main에는 `form_login_info`와 무관한 **직접 GET 링크** `a href="/vmp/common/login/viewLogin.do"`(icon_btn 블록)가 존재 — 스크립트 없이도 viewLogin 도달 경로가 있음.
  - 그 외 로그인 관련: `doLogout()`(연결 DOM 0건), `form_logout`(hidden 3), 외부 SSO 분기(`doDirectMenu03` → lms3.e-kpc.or.kr), 미로그인 시 `alert("먼저 로그인하십시오.")`.
- Aside 에이전트가 생성한 스크린샷 2장을 `근거/O-004-근거-*.png`로 보관.
- Aside 세션 자체 발생: 로드 시 페이지 스크립트가 공지 팝업(target 74) 자동 오픈 — 미개입.
- 한계: Aside 프로필 로그인 상태 비확인("connected"만 표시), Aside 응답 성공과 기능 성공 분리 원칙(spec §4)에 따라 위 결론은 **DOM 텍스트 근거**로 판정했고 Aside 자기 보고만으로 확정하지 않음. `form_common_btnLogin` 동적 submit 성공 자체는 Aside에서 실행하지 않았으므로 O-003(REA 실행 관찰)이 대신 보장.
- 상세: [근거/O-004-aside-form_login_info-요약.md](근거/O-004-aside-form_login_info-요약.md)
- Aside 사용 위치 확인: plan P1 "Aside는 필요한 화면 탐색·전환 재현·실패 조건 수집 지원"의 첫 실사용. Aside 단독 결과를 REA Evidence로 표기하지 않음.

### RQ-4 과정에서 남은 미확인
- ~~main의 `#form_login_info` 입력이 메인에서 직접 로그인에 쓰이는지~~ → **2026-10-20 O-004로 해소**: 비활성 폼(입력 hidden 2개, 참조 스크립트 0건). 클릭 진입은 `#btnLogin` → `jsCallLoginPage()` 동적 POST, 직접 GET 링크(`viewLogin.do`)도 병존.
- 화면 문구·메뉴 목록 전체 — Evidence 마스킹 정책상 원문 전체를 보관하지 않음. 재현 요구 확정 시 필요한 항목만 마스킹해 재확인.
- alert 오류 문구의 현업 의미 — 현업 인터뷰 대상 (원칙 §11 "현업 확인").
- 외부 SSO 분기(`doDirectMenu03` → lms3.e-kpc.or.kr) — 두 화면 밖이므로 관찰 중단, 재현 대상 아님(Non-goals 일치).

### 원칙 문서 관점 확인
- 원칙 §11 "현황 진단" 통과 기준("미확인 범위와 책임자 식별")에 따라 미확인 항목들을 위 목록으로 식별 완료. browser 관찰만으로는 서버 규칙·login.do 응답·OTP 발급을 복원할 수 없음(§11 209행)을 한계로 명시.
- 원칙 §13 "개인정보·토큰 유출, 페이지 지시 오인" 통제: 관찰한 inline 스크립트와 요청 파라미터(`sig`·`nonce` 등)는 데이터로만 취급하고 값을 보관하지 않음 (근거 README 정책).

## 8. 정적 vs 실행 관찰 대조 (RQ-5 · 2026-10-20)

| 항목 | 정적 근거 (GET 응답 HTML 내 inline 스크립트) | 실행 관찰 (headless 클릭 시나리오) | 판정 |
|---|---|---|---|
| main→로그인 진입 | `jsLoginRedirect()` 정의 확인, `#btnLogin`에 인라인 onclick 없음 | 클릭 → viewLogin.do 도달, history navigate + POST 기록 | **실행 확인** — 정의(정적)와 전환(실행) 모두 확보 |
| 로그인 submit | `fnCheckLogin()`→`fnLoginAction()` → `$.ajax POST login.do` 정의 | 입력·submit 금지로 미실행 | **정적만** — 런타임 응답 미확인. spec F4로 대체 구현 |
| OTP 분기 | `showOTPInput()`·`fnShowOTP()` 정의, 초기 `strStep=0` | 초기 상태만 관찰, 분기 도달 안 함 | **정적만** — 미확인 목록에 유지 |
| 접근성 상태 | 정적 분석 불가 | AX tree: 빈 이름, role=img | **실행 확인** — 접근성 결함은 실행 근거로만 확정 |

정적/실행 구분 원칙(근거 README §5) 준수: 정적 정의를 실행 동작 보장으로 쓰지 않는다. spec §7 AC-R1의 "정적/실행·한계·미확인 분리" 충족.
