## 5. P5 Aside 교차 검증 (AC-A1) — 완료

Aside CLI `exec`로 파일럿에서 "좌표·셀렉터 지시 없이 텍스트 이름/레이블/역할만으로" 경로를 탐색하게 했다: 헤더 '로그인' 버튼 이름 1건 매칭 → `/login`, 입력(label·maxlength 10/20)·버튼(`type=submit`) 식별, 빈 제출 시 인라인 `role=alert` 2건 + `aria-invalid`/`aria-describedby` 접근성 트리 DIFF로 포착, demouser/demopass 제출 → `role=status` 안내 문구·alert 0·세션 변화 없음 확인.

Aside 보고만으로 확정하지 않고 자동 테스트로 독립 재확인: E2E 7건(§4)이 Aside의 모든 주장(이름 매칭, 경계, 인라인 오류, 인증 요청 0건, 복귀)과 일치 → **AC-A1 충족**. 상세 근거: [../역설계/근거/O-005-aside-파일럿-검증-요약.md](../역설계/근거/O-005-aside-파일럿-검증-요약.md), Aside 캡처 3장(로그인화면·결과안내·오류상태) 보존.

한계: Aside는 텍스트 기반 접근성 관측만 제공한다(이미지를 직접 열람 불가 → 캡처 파일로 별도 보존). Aside 세션은 비밀번호를 자체 `[redacted]` 처리. Aside 단독 증거 금지 원칙 유지.

## 6. 구현 중 발견·교정 (사실 기록)

- Playwright E2E 실패 4건: 버튼 `aria-label="로그인 시도"`가 접근성 이름을 덮어써 `getByRole('로그인')` 실패 → **원인(aria-label) 제거**, 설계 §4 이름 규칙과 일치시키고 재실행 7/7 통과.
- vitest 기본 `include`가 `e2e/*.spec.ts`를 잡아 jsdom에서 실패 → `include: ['src/**/*.test.{ts,tsx}']`로 단위/E2E 경계 분리.
- `toHaveTextContent` 등 jest-dom 매처 미등록 → `src/test/setup.ts` + `setupFiles` 등록.
- `LoginPage` 단독 렌더는 라우터 훅 필요 → `MemoryRouter`로 단위 테스트 격리.
- preview 서버에 낡은 번들이 살아 있어 교정 후에도 구(舊) 마크업 스냅샷이 관측됨 → 서버 종료 후 새 빌드로 재실행해 해결. **경험 규칙: E2E 전 preview 서버 번들 신선성 확인.**
