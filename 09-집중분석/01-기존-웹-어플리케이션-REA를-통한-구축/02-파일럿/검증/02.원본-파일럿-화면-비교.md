# 검증 기록 — 원본 ↔ 파일럿 화면 비교 (남은 단계 1)

상태: **완료 (2026-10-20)** — 06.세션-인계-다음-단계 §남은 단계 1의 산출물.
방법: REA `capture_browser_scenario`(격리 청정 프로필, headless Chrome)로 원본·파일럿을 **동일 관찰 조건**(1280×720, ko-KR, Asia/Seoul, light, reduced motion)에서 캡처하고, 접근성 트리·스크린샷을 토큰 수준으로 대조했다. 사용자의 실시간 관측을 위해 Aside 가시 브라우저에 원본 `main.do`와 파일럿 `/`·`/login` 탭을 함께 열었다.

| 원칙 | 준수 결과 |

## 2. 화면 단위 대조 (DESIGN.md 토큰 수준)

### 2.1 메인 — `main.do` ↔ `/`

| 토큰 | 원본 관찰 사실 (O-006 main 캡처) | 파일럿 (`/`) | 판정 |
|---|---|---|---|
| 진입 구조 | table → rowgroup → cell 중첩 레이아웃 | `banner`/`navigation`/`main`/`contentinfo` 시맨틱 | **의도적 차이** (설계 D5) |
| 브랜드 | `img "vaatz logo"` (원본 자산) | 텍스트 링크 "VAATZ 파일럿 (데모)" | **의도적 차이** (자산 복제 금지, F3) |
| 로그인 진입 | `img "로그인"` (클릭 가능한 이미지, role=img) | `button "로그인"` (role=button) | **의도적 차이** (D1) — 이름 "로그인"은 보존 |
| 보조 내비 | `link "회원가입"`, `link "장바구니"` 등 이미지+링크 | `button "공지사항"/"자료실"/"마이페이지"` (미구현 안내) | 의도적 차이 (F3 범위) |
| 공지 | 링크 4건 + 날짜 텍스트 (실 데이터) | `region "공지 목록"` listitem 3건 (`[가상]` 접두) | 구조 대응, 데이터는 가상 |
| 데모 명시 | 없음 (실운영 사이트) | `contentinfo`: "파일럿 데모… 실제 업무 시스템과 연결되지 않음" | 파일럿 추가 (F3) |
| 이상 신호 | 페이지 로드 시 **공지사항 팝업 자동 오픈**(`popupMasterOpen.do`, Aside 관측에서 확인) — 팝업이 main 관찰을 오염시킬 수 있음 | 없음 | 원본 관찰 시 주의 항목 (신규 발견) |

### 2.2 로그인 초기 — `viewLogin.do` ↔ `/login`

| 토큰 | 원본 (O-006 viewLogin 캡처 · O-002) | 파일럿 (`/login`) | 판정 |
|---|---|---|---|

### 2.3 오류 상태 — 원본 `alert` ↔ 파일럿 인라인

- 원본(O-002 정적): 공백 시 `alert("…공백")` 전역 팝업 — 관찰 안전 원칙상 실제 트리거 금지로 **원본 런타임 미재현**.
- 파일럿(런타임 캡처): 빈 제출 → `textbox [invalid]` ×2 + `alert "아이디를 입력하세요"`·`alert "비밀번호를 입력하세요"` 인라인 2건, 전역 alert 0 (E2E §4-3과 독립 일치).
- 판정: 설계 D4/F4의 의도적 개선이 **접근성 트리에서 실측 확인** — 원본에는 없는 `[invalid]`·연결 오류·항목별 `role=alert` 패턴이 파일럿에만 존재.

## 3. 에이전트 관찰성 대조 (핵심 결론)

| 관찰성 항목 | 원본 | 파일럿 |
|---|---|---|
| 이름만으로 로그인 경로 발견 | 원본 main 캡처의 interactive 요소에서 `image "로그인"` 1건 (alt "로그인") — 이름은 있으나 role=img이고 jQuery 바인딩 의존. Aside AC-A1 이전 D-005/D-006에서 이미지 버튼 경로 불안정 확인됨 | `button "로그인"` 1건 — 이름+역할 확정, REA role locator 1발 클릭 성공(`ev_888a…`) |
| 입력 필드 식별 | `textbox` 이름 빈 값 — 좌표·DOM 탐색 없이는 "어떤 textbox가 아이디인지" 불확정 | `textbox "아이디"/"비밀번호"` — 이름+maxlength 안내로 즉시 식별 |
| 결과·오류 판독 | alert 문자열(팝업)·hidden 필드 — 구조화된 신호 없음 | `role=alert`/`role=status`/`[invalid]` — 접근성 트리 diff로 기계 판독 가능 |
| 화면 경계 식별 | 모든 화면이 공통 table 헤더로 유사 — `document.title` 동일 "VAATZ Marketplace" | title·h1·contentinfo 데모 표시로 화면 자격 구분 |

→ 에이전트 친화적 웹의 핵심 가정("role+이름+구조화 상태만으로 경로 발견→입력→판독 가능")이 **원본 대비 파일럿에서 성립**함을 동일 조건 캡처로 확인. AC-A2(이미지 버튼 이름 매칭 한계)의 원본 측 근거는 §2.1·§2.3의 img/alert 토큰이 근거가 된다.

## 6. Aside 보조 관측 (사용자 실시간 관측 포함)

- Aside 가시 브라우저에 원본 `main.do` 탭 + 파일럿 `/`·`/login` 탭을 동시 배치해 사용자가 양쪽 화면을 직접 비교 관찰할 수 있게 했다.
- Aside interactive 스냅샷(원본 main): `image "로그인" [ref=e2]`, `link "회원가입"`, `link "장바구니"`, 공지 링크 4건 — §2.1과 독립 일치.
- Aside 관측 신규 신호: `main.do` 로드 시 공지사항 팝업(`popupMasterOpen.do`) 자동 오픈 → 원본 메인 관찰 시 팝업 필터 필요.
